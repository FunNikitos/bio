# Совместная работа в bio

Codex и Gemini разрабатывают проект в одном Git-репозитории. Принятый результат хранится в `main`. У каждой активной задачи есть ветка `task/<slug>` и заметка `docs/progress/<slug>.md`, где slug — короткое имя задачи, например `profile-card`.

## Перед правками

1. Проверь `git status --short --branch`, `git worktree list` и `git remote -v`. Если есть доступный `origin`, выполни `git fetch origin`. Перед началом новой задачи обнови чистую `main` через `git merge --ff-only origin/main`, если такая ветка есть.
2. Прочитай `git log --all --oneline --decorate -20`, заметки в `docs/progress/` и код по задаче. Проверь активные ветки через `git branch --all --list 'task/*' 'remotes/origin/task/*'`. При работе через GitHub проверь также открытые PR и задачи по этой теме.
3. Если функция готова, проверь её по запросу пользователя. Если работа уже начата, прочитай заметку в её ветке, например `git show task/profile-card:docs/progress/profile-card.md`. После явной передачи продолжай с последнего коммита этой ветки. Если другой агент ещё работает, согласуй с ним пересекающиеся файлы через задачу или пользователя.

## Во время работы

- Оставляй основную папку на `main`. Для новой задачи создай отдельный рабочий каталог из корня проекта, например `git worktree add -b task/profile-card .worktrees/profile-card main`. Выполняй правки и проверки внутри него. Второй агент может одновременно работать в своём каталоге.
- Первым коротким коммитом добавь заметку задачи с автором, целью и областью правок. Обновляй эту же заметку при передаче или завершении. Укажи, что сделано, почему принято важное решение, какие проверки прошли и что осталось. Так каждая ветка ведёт свой журнал.
- Перед коммитом проверь `git diff` и `git diff --cached`. Сохраняй правки пользователя и другого агента. Включай в коммит только файлы текущей задачи. Если Git просит имя автора, задай его для одного коммита, например `git -c user.name=Gemini -c user.email=gemini@bio.invalid commit -m "…"`. Для Codex используй `Codex` и `codex@bio.invalid`.
- При работе с разных компьютеров опубликуй ветку через `git push -u origin task/<slug>`, чтобы другой участник видел прогресс. Для передачи укажи ветку, последний коммит и ближайший шаг.

## Завершение

Проверь результат по сценарию пользователя и выполни относящиеся к задаче проверки проекта. Запиши фактический результат и ограничения проверки. Если подключён GitHub, передай ветку через pull request в `main`. При локальном объединении сначала включи актуальную `main` в ветку задачи, повтори затронутые проверки, затем выполни `git merge --ff-only task/<slug>` из чистой `main`. При конфликте сохрани назначение обоих изменений и проверь итог.
