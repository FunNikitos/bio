# Установка bio на собственный сервер

Codex · 25 ноября 2026 · ветка `task/self-host-first`. Цель — описать путь от GitHub до первого опубликованного профиля. Область изменений — описание продукта в README и требования к первому релизу.

## Что получает владелец

Одна установка включает публичный профиль на `/` и закрытый редактор на `/admin`. Владелец управляет доменом, файлами, резервными копиями и обновлениями. Для обычного использования ему достаточно браузера и доступа к своему серверу. В открытом репозитории доступны исходники для самостоятельных изменений и работы с ИИ. После установки показ и редактирование профиля должны работать при недоступности GitHub.

## Путь новичка

1. Человек открывает в README «Установить на свой сервер». Инструкция объясняет, где взять адрес сервера, как открыть SSH и куда у регистратора добавить запись A для выбранного имени. Первый предлагаемый вариант для проверки — чистый VPS с Ubuntu 24.04 LTS и публичным IPv4.
2. Владелец запускает опубликованный в релизе установщик на сервере. Установщик спрашивает домен, проверяет Docker Compose, DNS и доступность портов 80/443. Установка недостающих системных компонентов требует согласия владельца. Если порты уже заняты, установщик сохраняет действующую конфигурацию и показывает путь подключения через существующий обратный прокси. При ошибке он объясняет, что исправить и как повторить шаг.
3. Установщик запускает публичный готовый образ из GitHub Container Registry, привязанный к версии релиза, и настраивает HTTPS. В терминале появляются адрес редактора и одноразовый код создания владельца с ограниченным сроком действия. На общедоступном экране нельзя присвоить себе новую установку без этого кода.
4. В браузере владелец задаёт пароль, выбирает оформление, добавляет аватар, имя и ссылки. Предпросмотр показывает черновик. После «Опубликовать» по основному домену открывается сохранённая версия. Следующие правки можно готовить, пока посетители видят прежнюю страницу.
5. Редактор позволяет скачать и восстановить настройки и медиа профиля. Данные хранятся отдельно от контейнера. Обновление сохраняет их, а перенос на другой сервер описан в инструкции. Пароли и ключи сеансов остаются за пределами переносимого архива профиля.

## Предлагаемая реализация

- GitHub хранит исходники, инструкцию и версионированные релизы. GitHub Actions собирает образ при выпуске. Для установки с готового образа не нужны Git, Node.js, Rust или аккаунт GitHub.
- Rust с Axum обслуживает вход, черновик, загрузки и публикацию. Редактор на Svelte и TypeScript собирается заранее и входит в образ. Посетитель получает готовую HTML-страницу со ссылками. Публикация переключает целую версию страницы и её ресурсов после успешной подготовки.
- Docker Compose запускает приложение и Caddy. Первый поддерживаемый сценарий — один владелец и один профиль на установку. Статический экспорт и дополнительные шаблоны могут появиться отдельно от этого пути.
- Для редактирования с ИИ нужен документированный формат настроек с номером версии. Владелец импортирует изменённые настройки, просматривает результат и публикует его обычной кнопкой.

## Когда первый релиз готов

Новому человеку дают только ссылку на GitHub, доступ к чистому тестовому VPS и управление тестовым доменом. Он доходит до своего профиля по HTTPS, добавляет ссылку в редакторе и открывает её как посетитель. При проверке также перезапускаем контейнеры, обновляем версию и восстанавливаем архив на второй установке. Аватар и ссылки должны сохраниться. Повторный запуск установщика должен сохранять владельца и действующий профиль.

Согласован основной сценарий продукта. Стек и тестовая ОС предложены для реализации. Эта задача меняет документацию. Установщик, образ и панель предстоит реализовать и испытать на чистом сервере. Ближайшая задача — сквозной прототип установки, создания владельца и публикации одной ссылки.
